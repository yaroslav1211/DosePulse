# Перевірки ЛР2

`make test` - окремі host-тести portable C. Використано assert.h: мінімальний runner не має автоматичних назв кожного кейсу, fixtures та mocking DSL,але перевіряє значення й послідовності callback явними assertions. NACK,timeout,unexpectedID та кожний збій ініціалізації тестуються без HAL. Реальний вектор із VCD додається після декодування,синтетичні вектори не позначаються виміряними.

Попередньо обраний поріг: >=80% рядків і >=80% гілок для Devices/App,окремо по модулях; це навчальний критерій для критичних одиниць/помилок/фільтрів,не доказ відсутності дефектів. Platform/Core/HAL перевіряються ARMзбіркою й симулятором,не включені у hostcoverage. Фактичні значення містяться у docs/evidence/lab2/coverage.

`tools/run_lab2_checks.py` виконує короткий benchсценарій за MCUtimestamps,зберігає команди,UARTraw та SHA256 виміряногоELF. Це ЛР2,не baselineS1/S2/S3 і не годиннийS2. Випробування реального обладнання відсутнє. CI додає build/test/coverage наPR і pushlab1/lab2; факт конфігурації не дорівнює успішному remoteCI,стан запуску перевіряється окремо.

Окремий powerdownексперимент: HX711 після hxoff/hxon у поточній моделі не повернув READY; прошивка зняла massvalid/stable,а не прийняла стару масу. Це виміряне обмеження цієї перевірки,не підтвердження фізичного recovery. Початковий validator перевіряв лише ACKкоманд і помилково надрукувавPASS для всього сценарію; цей consoleлог збережено як integration-powerdown-limit,вердикт скасовано. Фінальний стандартний сценарій не вимагає цієї додаткової powerdownфункції,перевіряє реальний NACK/відновленняMPU та кінцеву валідність усіх сенсорів.

tests/fixtures/mpu_wokwi.h отримано з першого повного burst0x3b у власному sigrokдекодуванні,а не зі штучного очікування. JSON містить SHA256 первинного VCD,14байтів і відповідні UARTодиниці. fake I2C повертає саме цей вектор; тести перевіряють0/0/1000mg,0mdps і24001m°C. Це одночасна перевірка conversion та зв'язку сигналів із UART,а не тест роботи фізичного MPU6050.
